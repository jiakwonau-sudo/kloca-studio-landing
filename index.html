Verification protocol

8단계, 순서대로

각 단계의 산출물이 다음 단계의 입력이 됩니다.

01

기준·범위 확정

무엇을 보고 제외하는지 문서로 먼저 정합니다.

02

증거 수집

계정·저장소·배포·DB·도메인의 실제 상태. 읽기 전용으로.

03

실제 테스트

서류가 아니라 직접 손으로. 재배포 재현, 백업 복원까지.

04

위험 등급화

발견사항을 P0부터 P3까지 분류하고 ID를 부여합니다.

05

판정

기계적 규칙으로. 인상도 해명도 끼어들지 못합니다.

06

수정·보완

BLOCK·FIX는 외주사가 고칩니다. 기록으로 남깁니다.

07

재검증

고친 항목을 다시 검증합니다. 재검증 없이 판정은 안 바뀝니다.

08

최종 리포트

모든 증거가 ID로 연결된 판정 리포트 한 부.

Verdict rules

판정은 규칙이 내립니다

KLoCa Assurance Standard v1.5 §5 원문

BLOCK
미해결 P0 — 지급·인수 보류. 즉시 사용 금지 항목이 남아 있으면 무조건 보류.
FIX
핵심 미해결 P1 — 조건부 인수. 소유권·보안의 문제는 고치기 전엔 안 넘어감.
PASS
P2·P3만 존재 — 인수 가능. 관찰사항으로 명시.
PASS 금지
핵심 기준 UNKNOWN — 확인 못한 항목이 있으면 PASS를 줄 수 없음.
"UNKNOWN은 정보 표시가 아니다.
핵심 통제항목이 UNKNOWN이면 사실상 검증 실패다."
