HOW IT WORKS

검증은 이렇게 진행됩니다.

막연한 "확인"이 아닙니다. KLoCa Assurance Standard v1.5 기준으로
항목마다 판정과 근거를 남깁니다.

1

사전 상담 무료

  • 인수 대상 앱의 구조 파악 — 외주 계약 형태, 개발사와의 현재 관계
  • 8개 항목 중 실제 검증 가능한 범위 확정
  • 검증이 불가능하거나 의미 없다고 판단되면 진행하지 않습니다
2

읽기 전용 권한 접수

  • 받는 것 — 관리자 계정 초대(읽기), 저장소 읽기 권한, 배포 문서, 도메인 등록 정보
  • 쓰기 권한은 받지 않습니다. 고객 시스템에 아무것도 변경하지 않고 검증합니다
  • 접수한 자료 목록을 먼저 공유하고 검증을 시작합니다
3

항목별 검증

  • 관리자 계정실제 로그인 테스트, 최고 권한 보유 여부
  • 저장소소유권 이전 상태, 메인 브랜치 보호, 커밋 이력 접근
  • 재배포배포 문서를 따라 직접 빌드·배포 재현 — 문서만 있고 안 되면 FAIL
  • DB읽기 접속 테스트, 백업 존재 및 복원 가능 여부
  • 시크릿소스코드 내 하드코딩 여부, 접근 통제 상태
  • 도메인등록 명의 WHOIS 대조
  • 운영 문서인수 후 단독 운영 가능 수준 평가
  • 비용청구서 기반 월 고정비 산출

판정 코드 PASS / FIX / BLOCK / UNKNOWN — KLoCa Assurance Standard v1.5 적용

4

검증 리포트 전달 자료 접수 후 3영업일 이내

  • 항목별 판정표 — 항목, 판정, 근거(확인 일시·방법·결과)
  • 종합 판정 — 인수 가능조건부 인수지급 보류
  • 수정 권고 — 우선순위(P0~P3)와 함께. 조건부는 해소 조건과 재검증 기준 명시
  • 리포트 설명 30분 미팅 포함
