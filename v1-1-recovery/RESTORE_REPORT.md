# KLoCa Lens v1-1 스캔·메뉴 복구

요약: 스캔 파일은 현재 서버에서 삭제되지 않았다. 크래시 수정 중 초기화 감시를 끄면서 스캔 화면이 생성되지 않는 문제가 생겼다. Git의 수정 전 코드로 기록·식탁 메뉴에서 React DOM 오류와 빈 화면을 재현했고, 스캔을 React 안에서 렌더하도록 만든 수정 후보는 DOM 통합 검사 9/9를 통과했다. 실제 브라우저의 수정 화면과 모바일 기기 검증은 미완료이므로 최종 판정은 PARTIAL이다.

## 확인한 대상

- 실제 주소: https://klocastudio.com/klocalens/v1-1/
- 실제 저장소: `jiakwonau-sudo/kloca-studio-landing`
- 확인한 main: `fedb331895448e36709b0de8c77fa7f35e65967d`
- 스캔 버전의 수정 전 기준: `96eef97f9e7908c9138cbe7775609d2f77b79571`
- 사용자 화면 기준: 아보카도 스캔 박스 → 사진·음성 검색창 → 식재료 카드, 오른쪽 홈·식탁·기록·대시보드·영양사 메뉴.
- 첨부 ZIP의 현재 실행 파일은 이 저장소의 v1-1 파일과 Git blob이 일치한다. 첨부에는 추가 `.bak` 파일이 있다.

앞선 `kloca-lens/chatgpt` 저장소 조사는 실제 주소의 이력이 아니었다. 앞서 작성한 패키지의 결론을 이 주소의 크래시 진단으로 사용하지 않는다. 이번에는 원래 주소, 연결된 실제 파일, 그 파일의 변경 이력으로 기준을 다시 확인했다.

## 수정 후보

- 스캔 박스, 사진 버튼, 음성 버튼, 로고 손잡이, 목록 접기를 React 컴포넌트로 통합.
- React가 관리하는 요소를 별도 helper가 삽입·삭제하는 구조 제거.
- 홈은 스캔 화면, 오른쪽 대시보드는 별도 대시보드 화면으로 연결.
- 기존 저장 키와 정상 기록·영양 계산을 유지.
- 형식이 잘못된 저장 자료는 원본 사본을 남긴 뒤 계산에서 제외. 저장 사본을 만들 수 없으면 원본 덮어쓰기를 막음.
- 화면 오류 경계를 추가하여 보기 하나의 실패가 전체 앱을 지우지 않게 함.
- 배포 코드의 기본 API 키 제거. 사용자 기기에 저장된 키는 유지.

앞선 함수 검사 22/22 결과도 패키지에 포함하되, 이번 원인 재현과 실제 DOM 검사와 구분한다.

## 미검증·배포 상태

- 관리형 미리보기는 proc 마운트 권한 오류로 시작할 수 없음. 별도 호스트의 브라우저는 실행 컨테이너 loopback 서버에 접근할 수 없음. 허용되지 않은 로컬 파일 접근이나 미리보기 환경 우회는 하지 않음.
- 수정본의 실제 브라우저 CSS·모바일 표시·터치·드래그·카메라·음성·이미지 분석·결제는 미검증.
- 운영 main과 원래 v1-1 주소는 변경하지 않음. 복구 후보는 별도 Git 브랜치와 ZIP으로 보관.
- `recovery/v1-1-before-crash`는 재현용 코드이다. 직접 배포하면 메뉴 오류가 돌아오므로 배포 대상으로 사용하지 않는다.
- 배포 후보는 `fixed/muse-version/` 전체 또는 Git 브랜치의 `klocalens/v1-1/` 전체이다.

## 재현 방법

1. `analysis/dom-tests`에서 `npm ci --ignore-scripts --no-audit --no-fund`.
2. 패키지 루트에서 `node analysis/dom-tests/qa-dom.cjs`.
3. 결과 JSON은 `recovery/qa/react-dom-results.json`에 생성됨.

패키지의 원본·재현 fixture에는 공개 번들에 들어 있던 기본 키를 제거했다. 원래 파일 자체는 기존 첨부와 Git의 지정 커밋에 보존돼 있다. 이 제거는 화면·메뉴 오류 재현에 영향을 주지 않는다.
